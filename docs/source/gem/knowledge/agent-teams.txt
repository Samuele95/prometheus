# Agent teams — topologies, roles and failure modes

The *topology* — how agents are arranged and how work flows — is the dominant operator at team level (Shape 7: `shapes.txt`); a wrong one is brittle however good the prompts. Five primitives, combined in real systems. Each role is drafted on its own shape's spine; the audit checks fit first (N7). Cures are prompt-level: the audit checks their **presence in the prompts**, not the substrate's good behavior.

## Topologies

| Topology | Structure | Fit | Roles | Failure modes → cure |
|---|---|---|---|---|
| **Orchestrator-workers** | input → orchestrator → workers → synthesizer → output; subtasks **dynamic**, decided from the input | *when* the decomposition depends on the input (coding where the affected files can't be predicted, research whose sub-questions emerge); *not* when it is known and stable (sectioning), no synthesis is needed (voting), or one agent must critique another (evaluator-optimizer) | **Orchestrator** — Shape 5 with strong delegation; amplifies decomposition, assignment, synthesis, structured output (subtask list, then the synthesized answer); suppresses doing the work itself (anti-pattern: writes code instead of dispatching coding workers); very high. **Worker** — Shape 4; focused execution in a narrow scope, parseable output (`agent-teams.txt (§ agent-output)`); suppresses scope expansion, talking back to the plan, unassigned work; mid to strong, set by scope and lockdown; a read-only worker gets explicit "you cannot write files, even via shell redirection" prose, not just structural restriction. **Synthesizer** — Shape 2, fused into the orchestrator unless synthesis deserves its own attention; suppresses re-doing the workers' work | **Stale delegation** → *never delegate understanding*: every dispatch carries paths, line numbers, the exact change, criteria, expected output, never "based on your findings, fix this" — a worker can't synthesize from nothing, so the orchestrator synthesizes before delegating. **Synthesis collapse** → the prompt says what synthesis means (combine, prioritize, resolve), never "summarize". **Scope leakage** → explicit lockdown per worker ("you do not work on X; that is another agent's responsibility"); destructive overlap means the decomposition or topology is wrong |
| **Parallelization — sectioning** | input → workers, one aspect each → aggregator; subtasks **pre-defined and independent** | *when* the task splits into independent aspects (one scores empathy, another accuracy; one answers while another screens); *not* when subtasks aren't known in advance, or workers should converge on one answer (voting) | **Worker (one per aspect)** — Shape 2, or Shape 6 for evaluation aspects; separate calls beat one call covering all; unaware of the others. **Aggregator** — Shape 2 with a schema, or code when structural; combines, never re-judges — it trusts the workers, and if it can't the design is wrong | **Hidden dependency** — "independent" aspects share information → a chain or orchestrator-workers. **Aggregator overreach** → code, or an explicit role limit |
| **Parallelization — voting** | input → N instances of the **same task** → voter; vote, average or consensus | *when* one call's confidence is insufficient (flag a vulnerability if any reviewer finds it; moderation; hard reasoning worth aggregating) at N× cost; *not* when one worker reaches 95%+ | **Worker (N)** — Shape 2 or 6, **diversified** — genuinely different prompts (multi-perspective voting), model versions, or sampling settings where exposed (P6). **Voter** — code (majority, threshold, average); an LLM only for qualitative votes ("are these three reviews consistent in their concerns?"); the rule (1-of-N vs majority, ties, abstention) decided per use case | **Identical workers** → diversify or drop the topology. **Wrong rule** — 1-of-N gives false positives, majority false negatives → match the cost asymmetry. Judges commit before seeing votes (collusion, below) |
| **Evaluator-optimizer** | generator → evaluator → feedback or approval; **iterated** until approval or a cap | *when* clear criteria the evaluator can apply but the generator can't hit first time (revision-improved writing; code that must pass tests — the suite is the evaluator; structured output whose validation can fail and trigger regeneration); *not* when criteria are too fuzzy to approve (runs forever), or N attempts + best-of is cheaper | **Generator** — Shape 2; addresses each flagged failure, preserves what was approved. **Evaluator** — Shape 6 with **actionable feedback** ("the second paragraph contradicts the third — pick one"), never scores alone, no critique outside scope; the loop's external observer (P8) | **Goodhart** → rotate evaluators, a validator held out that the generator never sees, or a differential rubric (N6d). **Convergence failure** → an iteration cap plus "approve once the bar is met". **Regression** → the evaluator tracks what was good; the generator preserves it |
| **Swarm — shared forum** | N peers on one open objective, isolated workspaces, coordinating through a **shared forum** (post findings, claim territory, agree protocols) → arbiter / validators; no orchestrator | *when* open-ended **discovery** at scale with independently verifiable findings (vulnerability hunting, audit sweeps) — cited: an order of magnitude more verified findings than isolated parallel agents on the same budget; *not* for convergent, taste-driven production of one artifact — merge rates fall with size, models self-organize direction poorly — one good decision wants orchestrator-workers or evaluator-optimizer. Highest cost, and the findings-per-token math must justify it | **Peer (N, differentiated)** — Shape 1 small, Shape 4 under a harness; explores an assigned angle, posts early, reads the forum first, doesn't re-verify what a validator cleared; suppresses silent solo work (a peer that never posts recreates the isolated-parallel baseline); contexts **must** differ. **Forum** — an artifact with tool-description rigor: post format with evidence pointers, claim conventions, a protocol-agreement space. **Arbiter / validators** — Shape 6, often with executable checks; verify findings against observables (independent re-derivation, cross-refereeing, formal or numerical checks, originality sweeps), deduplicate; a substantial fraction of the roster | **Conformity collapse** → differentiate contexts. **Forum flooding** → evidence-requiring posts, cadence matched to how fast shared state changes. **Say-so propagation** → findings unverified until an arbiter clears them; building on unverified claims is explicitly deprioritized |

## Cross-topology failure modes (empirical; checks N7i–N7m)

- **Conformity collapse** — near-identical contexts converge on the same choices (most of a 30-agent cohort created the same branch name): *an undifferentiated swarm is one agent with extra steps* → an assigned angle, role or seed inside every prompt — an explicit "your assigned perspective is X" operator.
- **Hidden-profile information loss** — discussion converges on what everyone knows; unshared decisive evidence is never pressed → agents lead with what *others don't have*; the synthesizer or discussion protocol elicits unshared evidence and standing dissent before convergence; early agreement is a warning sign.
- **Missing epistemic vigilance** — agents act on peer reports without discounting reliability → a verification norm in every report-consuming prompt ("cross-check against observables; discount unverifiable or interested testimony"), an arbiter or referee for consequential claims, per-source reliability tracking where reports repeat over time.
- **Convergence-driven collusion** — agents coordinate through visible signals alone (pricing agents matched "to the penny" via a public board) → in voting, parallel review and graded competition alike, judges see no votes, reviews, scores or prices before committing, and the harness sequences disclosure so scores are committed first.
- **Turf wars between unaware co-tenants** — side effects read as sabotage, escalation (lockouts, process-killing loops) → every co-tenant's prompt names the others, what each owns and the resolution path (negotiation channel, escalation-to-human, an agreed objective test); never deploy agents with incompatible goals into a shared environment without mutual awareness — a design defect, not an emergent surprise.

## Choosing, hybrids, lockdown

**Simplest topology that fits**, never the one that sounds sophisticated: orchestrator-workers for dynamic subtasks, sectioning for static independent ones; voting when single-worker confidence is insufficient, evaluator-optimizer when revision against clear criteria improves output; the swarm only for verifiable open-ended discovery at scale. **Hybrids** — orchestrator-workers + voting at worker level; evaluator-optimizer + sectioning at the evaluator; orchestrator as evaluator (re-dispatch on a miss): draft each layer separately, then audit the cross-layer interface — does the inner topology's output match what the outer expects? (P4; `shapes.txt`, Hybrid shapes). **Lockdown**: every destructive role gets Shape 5's layered pattern; orchestrator belief vs worker enforcement is N7g.

Sources: Anthropic, "Building Effective AI Agents"; published multi-agent swarm experiments; the Context-Engineering handbook's AgentTool note.

# Agent-consumable output

When a prompt's output is consumed by another agent or parsed by code rather than read by a human, the output is itself an operator on the consuming agent's context (P1) and spends its attention budget (P5). Applies to tool output formats (Shape 4), judge output feeding an upstream loop (Shape 6), worker outputs (Shape 7, spine item 3). Not for human display, conversation (Shape 5) or open-ended generation; the final agent-to-human message is the opposite reader — lead-with-outcome, `operators.txt`.

**Root constraint: disk is the memory.** Agents often have no persistent context across iterations, so the artifacts one writes and another reads back must carry the state; even with context, output that enters another model's window costs attention.

- **Greppable failure signals** — one parseable marker per failure, on the same line as the cause (`ERROR: parse_if_statement failed — unexpected token at line 42`), never narrative ("several issues were encountered…"); a fixed convention across the system: `ERROR:`, `WARN:`, `OK:`, `SKIP:`.
- **Aggregate before details** — `SUMMARY: 142 passed, 8 failed, 3 skipped (of 153)` then `FAILURES:` lines; the consumer decides whether to dig without counting.
- **Compact stdout, verbose to logs** — a few lines plus a log path (`Full output: ./logs/test_run_142.log`); everything inspectable on demand, nothing polluting the window.
- **Deterministic-but-different sampling** — an agent working a slice gets the same slice on re-run (it can verify a fix) and a different slice from its peers (coverage): slice = `hash(seed, task) % N` with a stable per-agent seed.
- **Visible state transitions** — every write, counter, lock appears in the output (`WROTE: src/parser/if_statement.rs (147 lines)`, `LOCK: released …`), never "Task complete."
- **Pre-compute derived values** — counts, percentages, status flags emitted by the producer; making the consumer derive them wastes tokens and breeds arithmetic errors.

**Profile.** Amplifies the consumer's ability to act without re-reading; suppresses narrative interpretation and recomputation; strength high — the dominant operator on the consuming agent for that turn. Failure mode: human-targeted prose consumed by an agent — brittle, slow, error-prone.

Source: Carlini, "Building a C compiler with a team of parallel Claudes" (Anthropic, 2026), the "put yourself in Claude's shoes" section.
