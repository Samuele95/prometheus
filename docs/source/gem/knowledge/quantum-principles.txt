# Quantum-semantic principles — canonical formalism, glossary, and operational mapping

This file is the **single canonical source** of the framework's quantum-semantic formalism. Every other file uses the vocabulary and cites principles as bare references (P1…P11) without re-explaining them; "§" anchors are retired. If a term or claim is not in this file, the framework does not use it.

## Epistemic charter (read once, applies everywhere)

The quantum-semantic formalism is this framework's **generative core**: prompts are operators, readings live in superposition, commitment is measurement. The framework was built from these findings, and field use of its outputs is the standing evidence that the design practices they generate work.

Three commitments keep the core strong:

1. **Dual anchoring.** Every principle carries two anchors: its *operational rule* (what the architect does) and its *empirical anchor* (the measured evidence and mechanism that ground the rule — position bias, instruction-count effects, conflict topology, sampling behavior). The formalism unifies; the anchors ground. A principle missing either anchor is incomplete.
2. **Evidence wins, the mapping updates.** The framework holds its own theory to the standard it holds prompts to (P7): claims are measured, and when a measurement contradicts the current mapping, the mapping is revised — never the practice frozen to save the theory. Concretely: the semantic Bell-test results (Agostino et al. 2025) are treated as *suggestive, not probative* — the largest run (N = 200, |S| = 1.83) does not violate the classical bound and no-signaling was not controlled — so the framework asserts operator structure, superposition, and measurement as its working calculus, and asserts nothing about physical quantum processes in LLMs. Nothing downstream depends on that open question.
3. **Build-time formalism, runtime artifacts.** The formalism is the *architect's* language — used in this framework's procedure and in its internal operators (Monitor, Analyze, verifiers). Shipped user prompts are collapsed artifacts: they must work on any substrate that has never heard of the formalism. A shipped prompt that requires the downstream model to know the formalism is a defect.

**Sources of the formalism.** Agostino, Le Thien, Apsel, Pak, Lesyk & Majumdar, *A quantum semantic framework for natural language processing* (arXiv 2506.10077, 2025; Springer CCIS 2659, 2026) — semantic degeneracy, observer-dependent actualization, Bayesian sampling. The *Context-Engineering* handbook (davidkimai, module 13) — the operator practice and the permutation protocol this framework extends. Quantum-cognition literature (Pothos & Busemeyer 2022) — the precedent for using a non-Kolmogorovian calculus as a working model of interpretation. Empirical anchors are cited per principle below; the ones that can expire (runtime parameters, model generations) carry their date inline until the refresh phase collects them in a runtime-notes reference.

## Glossary — term → operational meaning → empirical anchor

| Term | Operational meaning | Empirical anchor |
|---|---|---|
| Operator Ô | A prompt section's transformation of the output distribution; profile = what it amplifies / suppresses / mixes; strength = how hard it projects | Conditioning under a finite attention budget |
| State \|ψ⟩, superposition | The weighted set of plausible readings of an input or requirement, before commitment | Models under-detect their own missing information (QuestBench 2025) — so the *architect* enumerates readings |
| Collapse, measurement | Committing to one reading or one output; irreversible within a run | Decoding; a run is one sample of the distribution |
| Non-commutativity [A,B] ≠ 0 | Section order changes behavior; first operators set the subspace | Causal-attention position bias (Wu et al. ICML 2025; Ok & Lee 2026: 14.7-pt order gap on decoder-only, ~0 on bidirectional); lab defaults: bulk data first, directives last, load-bearing directives repeated at both ends of long prompts |
| Interference | Deviation of joint instruction-following from the independent-product baseline pⁿ; constructive or destructive | Count effect predicts most degradation (Harada et al. 2025, ~10% error from count alone); ~12% of instruction pairs genuinely interfere (Anand & Chattaraj 2026); operational test = the contradiction audit |
| Preferred basis | The authority order that resolves conflicting operators | Instruction hierarchy: platform > system > developer > user (OpenAI Model Spec; cross-lab) |
| Measurement parameters | The runtime knobs that select mode vs. distribution. Substrate-relative (P6): temperature/top_p on legacy runtimes; effort / reasoning_effort / thinking_level on adaptive-reasoning runtimes, where sampling knobs may be rejected outright | Runtime docs, dated (e.g. temperature → HTTP 400 on Claude Opus 4.7+/Sonnet 5) |
| Tomography, min-N | Estimating a distribution requires N samples; a single run licenses no conclusion — about a prompt, an agent, or this framework | Self-consistency; pass@k vs pass^k; the min-N gate in manage mode |
| Observer | The measuring apparatus = rubric + model + context, as one unit. No system tomographs itself: evaluation requires an *external* observer in a fresh context | Self-evaluation bias (Panickssery 2024; Huang ICLR 2024); pointwise self-scores: ICC 0.53–0.78, ~45% within-question noise (2026) |
| Substrate relativity | Operator strength and measurement parameters are relative to the substrate acting as ground (P9, P6) | Cross-lab 2026 guidance: prescriptive operators over-project on high-instruction-following substrates |

## The principles

**P1 — Prompts are operators, not keys.** You construct behavior by transforming the distribution, not by finding magic words. *Rule:* design every section by its amplify/suppress/mix profile (`operators.txt`); debug by asking "which projection is wrong?", not "which keyword is missing?". *Anchor:* conditioning + attention budget; sections with no profile are decoration and are struck (`audit.txt`, check D).

**P2 — Ordering is structural.** Operators don't commute; the composition order is part of the design. *Rule:* bulk state (documents, data, code) early; active directives late; on long prompts, repeat load-bearing directives at both ends; strongest framing operators open the sequence. Departures are deliberate and recorded. When a prompt misbehaves, try reordering before adding content. *Anchor:* position bias is mechanistic (causal attention) and direction is substrate-specific — hence P7's measurement rather than dogma; Anthropic measures up to +30% from data-top/query-bottom.

**P3 — Superposition is preserved at design time and collapsed deliberately at run time.** Ambiguity is information; *when* to collapse it is a design decision, not an accident. *Rule (design time):* enumerate the plausible readings of the user's intent with weights; ask only where readings diverge architecturally (the interview's forced-choice discipline) — preserve the superposition on architectural choices (shape, audience, runtime), where asking is cheap and a wrong guess is costly, and default tactical ones (file names, capitalization), stating the default; record what was deliberately left open and its collapse condition. *Rule (run time, encoded in shipped prompts):* collapse to the dominant reading when it is clearly ahead (~30% margin) and proceed, stating assumptions; on near-degenerate readings with architectural consequence, perform **one targeted measurement** — a single clarifying question — *only if the deployment is interactive*; unattended deployments always collapse to the most probable reading and record the state vector in the assumptions-and-deviations file. The enumeration pattern is the same everywhere it appears — 2–3 readings with weights, the collapse condition, a proposed default — in loop boundary handoffs facing an architectural decision as in the deviations file; and where a one-shot prompt's output format can carry it, an ambiguous input returns the weighted readings rather than one forced answer. A shipped prompt that tells an unattended agent to ask a question is malformed. *Anchor:* labs converge on resolve-with-declared-assumptions at run time; models are poor at identifying their own missing information, which is why enumeration is the architect's job.

**P4 — Combination interferes; the baseline is the independent product.** Adding instructions is never free. *Rule:* expect joint compliance ≈ pⁿ from count alone — so minimize n; treat deviations below the baseline as destructive interference and hunt the conflicting pair; run the **contradiction audit** (the operational interference test) on every draft; resolve surviving conflicts by the preferred basis (authority), or delete one side. *Anchor:* count effect ~10%-predictable from n; ~12% of pairs interfere with a reproducible topology; "conflicting rules create more instability than missing detail" (OpenAI, 2026).

**P5 — Projection is selective; the budget is finite.** Every operator spends shared attention and narrows the distribution — that is its job. The failure modes are over-projection (collapsing states the substrate would have resolved better: P9) and budget waste (operators that buy no behavior). *Rule:* smallest viable operator set *at each moment* — always-loaded core stays light, detail lives in on-demand artifacts; every section names the behavior it buys or is struck; place context so it is in-budget when needed (P2). *Anchor:* leaner system prompts measurably outperform (OpenAI 2026: +10–15% quality at −41–66% tokens); "smallest set of high-signal tokens" (Anthropic).

**P6 — Measurement parameters are substrate-relative.** The knobs that choose mode versus distribution belong to the runtime, not to the theory. *Rule:* on legacy runtimes, temperature/top_p are live levers (0 for extraction; >0 with multiple samples for exploration). On adaptive-reasoning runtimes, the lever is effort / reasoning_effort / thinking_level — recommend an effort level, never a thinking-token budget where budgets are deprecated — sampling knobs may be **rejected by the API**, and recommendations must name the runtime's actual parameters — from the runtime's current documentation (the runtime notes, once the refresh phase collects them), never from memory. Exploration on such runtimes uses multiple samples and prompt-level diversification, not temperature. *Anchor:* temperature/top_p → 400 on Claude Opus 4.7+/Sonnet 5; absent on OpenAI reasoning models; Google recommends removal from Gemini 3.5.

**P7 — The framework is empirical about itself: tomography over anecdote.** Structure is measurable; single measurements are noise. *Rule:* the **permutation test v2** — at least 3 orderings × at least 3 samples per ordering, scored on a *task metric* (never output similarity between two single runs: a single-sample comparison confounds ordering with sampling noise — the framework's own min-N principle applied to its own test). Prompt quality claims come from the eval harness: with-skill vs. without, binary assertions with quoted evidence, pass^k across trials. Field experience seeds the eval set; the eval set turns it into a measurement. *Anchor:* Google's own guidance recommends reordering experiments; pass^k (τ-bench; Anthropic evals guidance 2026).

**P8 — Meaning is observer-dependent; evaluation needs an external observer.** The same operator yields different distributions on different substrates, and a judge is a rubric+model+context *pair*, not a rubric. *Rule:* condition every delivery on the named runtime — a prompt that must run on several runtimes is designed for the lowest common denominator, with runtime-specific extensions layered on top; treat judge calibration as part of the apparatus (the judge model's own biases are part of the operator: anchors, bias controls, validation against human labels before verdicts drive decisions); and **never let a system tomograph itself** — what clears a draft for delivery is a fresh-context observer's evidence-required binary verdicts; the drafting session's own 1–10 score is a **self-report**, labeled as one when delivered: it discloses and asks for revision, it never clears the delivery, because scorer and scored share a context. *Anchor:* self-evaluation bias and self-score noise are among the best-replicated results in the 2024–2026 evaluation literature.

**P9 — Operator strength is substrate-relative.** A prescriptive operator that corrected a weak substrate over-projects on a strong one. *Rule:* calibrate default strength down as substrate capability rises: brief general instructions on adaptive-reasoning substrates (while stating scope — they read literally); enumeration, repetition at both ends, and explicit CoT scaffolds on legacy substrates. Intensity language (CRITICAL/MUST, all-caps) is reserved for true invariants on every tier. Capability lockdown for destructive roles stays layered and loud on every tier — its justification is risk, not substrate weakness. *Anchor:* "skills developed for prior models are often too prescriptive… and can degrade output quality" (Anthropic, Fable 5, 2026); "treat it as a new model family" (OpenAI, 2026); "may over-analyze verbose techniques for older models" (Google, 2025–26).

**P10 — Rationale extends the operator's reach.** A rule with its reason keeps projecting where the enumeration runs out. *Rule:* attach a one-line *because* to every load-bearing constraint; prefer principle-plus-rationale over exhaustive lists; when examples carry a rule, vary their surface so they teach the rule, not the surface. *Anchor:* "Give the reason, not only the request" (Anthropic, Fable 5, 2026); explanation-based instruction generalizes where demonstration lists do not.

**P11 — Suppression names its target, and naming partially amplifies.** A prohibition is never a clean projection to zero. *Rule:* positive framing for behavior-shaping ("write plain declarative sentences" over "don't be flowery"); named prohibitions only for lockdown and demonstrated sharp edges, compensated by rationale (P10) and, on legacy tiers, repetition. *Anchor (low-confidence, held per charter rule 2):* the labs' stated rationale is steerability and conflict cost, not priming; the one direct confirmation is tag-leakage on Opus 5 ("naming thinking tags increases leakage"). The operational rule stands on the labs' guidance either way.

## Measurement protocols (the formalism's own instruments)

- **Contradiction audit** (P4): enumerate every pair of directives a model cannot satisfy jointly, or that answer the same question differently; fix by deletion, merger, or preferred-basis ruling. Runs on every draft and on this framework's own files.
- **Permutation test v2** (P2 + P7): ≥3 orderings of the strongest operators × ≥3 samples × task metric; adopt the best ordering; record the choice and its evidence. Reserved for high-stakes prompts; shipped as a spec at delivery (SKILL.md, Phase 6), run by the user.
- **External-observer evaluation** (P8): fresh-context grader, binary assertions, quoted evidence, pass^k across trials; with-skill vs. without-skill for the framework's own releases.
- **Min-N gate** (P7): no adaptation, no conclusion, no principle revision on a single run.

**Library prompts** (Agostino et al., Appendix B.1) and where their logic now lives, so none needs invoking directly: A (ambiguity preservation — weighted interpretations in the output) and I (superposition requirement analysis — weighted basis states with collapse criteria) → the P3 design-time enumeration, used when a requirement should not collapse yet or the task description is unusually ambiguous; G (Bayesian interpretation audit — generate, cluster, report the distribution) → the same enumeration when the task description itself is ambiguous; N (observer-aware drafting — one message, several observers, controlled collapse) → P8, for outputs read by several audiences; L (ordering optimizer) → the permutation test v2; D (commutativity test, two orderings compared by fidelity) → superseded by the permutation test v2, since a single-sample fidelity comparison is retired (P7).

## Usage rules for the rest of the framework

1. Other files use glossary terms freely and cite principles as (P1)…(P11). No re-definitions, no "§" anchors, no per-file quantum re-explanations — canonicity is what makes the formalism cheap.
2. Shipped user prompts contain collapsed, substrate-ready language only (charter rule 3). Framework-internal operators (Monitor, Analyze, package verifier) may use glossary terms, and must still define their I/O operationally inline, as they do.
3. Claims retired and not to be reintroduced: "CHSH violations rule out semantic hidden variables"; "each instruction destroys information" as a general statement; temperature guidance for runtimes that reject it; single-sample fidelity comparisons.
4. When new empirical results land, they update the *anchor* column and, if needed, a principle's rule — through the framework's own change process (evals before edits), per charter rule 2.
